# 졸업로드맵 시연 진행표

이 문서는 현재 기능을 설명하기 위한 **선택적 6분 시연 초안**입니다. 최종 리허설 완료를 현재 작업의 완료 조건으로 삼지 않습니다. 팀원 자료 통합과 교수 수업자료 대조는 자료를 받은 후 진행하며, 그 결과에 따라 설명 순서를 조정합니다. Windows 검증과 시연 영상 제작은 2026-10-23 사용자 결정으로 제외합니다.

권장 길이는 약 6분입니다. 윤석현 담당인 **이수 진단·수강 계획 계산**에 가장 많은 시간을 배정합니다. 팀원이 발표 시간을 정하면 각 구간을 같은 비율로 조정하면 됩니다.

시연 대상은 가상 학생 **김가온**, 성결대학교 2024학번 컴퓨터공학과 전공심화입니다. 기본 시점은 2026년 3학년 2학기, 목표 마지막 수학 학기는 2027-2입니다. 공학인증은 제외합니다. 성적표·프로필은 전부 더미이며 공식 증명서가 아닙니다.

## 시작 전 준비

- README에 따라 앱과 필요한 로컬 서비스를 실행하고 **01 · 목표까지 준비 가능한 사례**를 불러옵니다.
- 첫 모델 다운로드와 RAG 색인 생성을 미리 마칩니다. RAG 상태가 `chroma_fastembed`인지 확인합니다. 대체 어휘 검색이면 그 상태를 숨기지 않습니다.
- AI API를 실제 연결했는지 확인합니다. 키가 없으면 **로컬 계산·검색**으로 시연한다고 말합니다. 모의 응답 테스트를 실제 API 응답으로 소개하지 않습니다.
- 화면의 현재 확정 학점이 90, 수강 중이 15, 전공이 45/63인지 확인합니다.
- 사용할 사례 01·03·05·09·10의 위치와 **계산 과정·출처** 탭을 확인합니다.
- 학사일정은 2026년 실제 제공 날짜를 사용합니다. 2028년 날짜는 자료가 없다는 응답을 보여 줄 수 있습니다.
- 기존 캡처를 참고한다면 실제 실행 화면과 파일 버전을 구별합니다. 시연 영상은 이번 산출물에 포함하지 않습니다.

## 윤석현이 말할 문장과 화면 동작

### 1. 정상 준비 사례

**사례01 → 사례 불러오기 → 대화로 확인 → 나 졸업 괜찮아?**

> 지금은 3학년 2학기 재학이라 졸업요건을 모두 충족한 상태는 아닙니다. 확정 학점은 90, 현재 수강 중은 15입니다. 수강 중 과목과 내년 두 학기 각 9학점의 후보를 통과하면 총 123에 도달할 수 있습니다. 그래서 현재는 미충족, 목표까지는 조건부 가능으로 구별했습니다. 채플 추가 1학기, 8학기 등록, 작품 심사 통과도 필요합니다.

**진단·수강 계획 → 수강 중 과목을 모두 통과한다면?**를 엽니다. 현재와 예상 값을 비교합니다. 계획의 학기별 상한·후보 과목·미확인 개설 표시와 **이 계획이 성립하는 조건**을 보여 줍니다.

> 계획기는 남은 전체 학기를 동시에 계산합니다. 같은 과목을 중복 추천하지 않고, 4학년 최소 9학점과 학기 최대 18·연간 36학점, 설계 순서를 확인합니다. 교육과정상 후보이므로 실제 개설과 시간표, 여석은 따로 확인해야 합니다.

세부 최적화 설명은 [윤석현 계산로직 설명서](윤석현_계산로직_설명.md)의 전체 학기 배치 예시를 사용합니다. 학기별 구체 과목은 실행 결과를 읽고, 과목명이나 배치를 외워서 다른 결과를 설명하지 않습니다.

### 2. 위험 사례: 목표까지 학점이 모자람

**사례03 · 총학점 부족 위험 → 같은 질문**

> 이번 사례는 현재 38학점입니다. 수강 중 15학점을 모두 통과해도 53이고, 남은 두 정규학기 최대 36을 더해도 89입니다. 총 123까지 34학점이 남으므로 현재 목표 학기에는 위험하다고 답해야 합니다.

손계산: `38 + 15 + 18 + 18 = 89`, `123 - 89 = 34`입니다. 화면의 **계획을 모두 이행해도 남는 부족분**을 확인합니다. 단순히 ‘더 열심히 들으면 괜찮다’고 답하지 않습니다.

### 3. 반례: 총123인데도 미충족

시간이 허용하면 사례03 다음 **사례05 · 123학점이지만 필수과목 누락**도 보여 줍니다.

> 이 사례는 총 123학점입니다. 하지만 사회봉사가 없고 교필은 13학점이므로 미충족입니다. 총합 검사와 지정 과목 검사를 분리했기 때문에 이 오류를 잡습니다.

이 사례는 **2027-2를 마친 미래 시점의 별도 시험 데이터**입니다. 현재 기본 3학년 학생이 이미 123학점을 취득한 것처럼 말하지 않습니다.

### 4. 재수강과 계산 근거

**사례09 · 승인 재수강을 한 번만 인정 → 계산 과정·출처**

> C프로그래밍 F 원행과 승인 재수강 A0 행이 있습니다. 두 행을 더하는 것이 아니라 유효한 재수강 학점 3만 인정합니다. 화면에 어떤 행이 제외됐고 왜 인정됐는지 표시합니다. 이것은 AI가 만든 추론이 아니라 계산 코드가 남긴 기록입니다.

`입력 성적표 보기`를 열면 `retake_of`가 원행을 가리키고 승인 값이 있다는 점을 짚습니다. 재수강 행이 있다는 사실만으로 모든 대체 승인이 자동 확인된다고 말하지 않습니다.

### 5. 자료 없음과0의 차이

**사례10 · 채플 자료 누락 → 같은 질문**

> 채플 자료가 없으면 0학기라고 추정하지 않습니다. 현재 확인이 필요하다고 표시하고, 신뢰할 수 있는 계획을 만들기 전에 자료를 보완하도록 합니다.

가능하면 **계산 과정·출처**에서 학교 근거와 더미 입력 출처를 구별해 보여 줍니다. 학칙 파일명의 날짜를 등록일로 만들지 않는 것도 설명할 수 있습니다.

## 중간에 문제가 생겼을 때

| 상황 | 진행 방법 | 피할 말 |
|---|---|---|
| API 키 미설정·인증 실패 | 연결 상태를 알리고 로컬 계산표·검색 결과를 설명 | “실제 Claude/OpenAI 응답 검증 완료” |
| RAG 모델 다운로드·서비스 실패 | backend와 경고를 확인. 원문 PDF와 출처표로 근거 설명 | “벡터 검색이 정상 동작했다” |
| CSV 오류 | 오류 행·열을 보여 주고 더미 사례로 복귀 | “일부 행을 빼면 충족하므로 괜찮다” |
| 계획 탐색 확인 필요 | 입력·탐색 상태·남는 부족을 보여 줌 | “계산 실패니까 졸업 불가” |
| 실제 시간표 질문 | 교육과정상 후보와 미확인 사항을 설명 | “이 시간표로 수강신청이 확정된다” |
| 캘린더 앱 질문 | 승인한 ICS 파일을 사용자가 가져오는 방식임을 설명 | “사용자 캘린더에 자동 등록됐다” |

실패가 해결되지 않았으면 시험 기록에 실패와 조건을 적습니다. 현재 실행이 실패했는데 과거 캡처를 실시간 성공으로 소개하지 않습니다.

## 팀 통합 후 설명 자료 점검

1. 정상·부족 사례 모두 결론, `reason`, 근거자료, `meta`가 보이는지 확인합니다.
2. 현재 90, 수강 중 포함 예상 105, 목표 후보 포함 123을 구별해 말할 수 있는지 확인합니다.
3. 123학점이어도 필수·채플·작품 누락을 잡는지 확인합니다.
4. 재수강·자료 누락 사례에서 ‘왜 그 결론인지’를 계산표로 설명합니다.
5. 테스트 통과 수·API 실제 연결·벡터 검색 상태는 최신 실행 기록으로 발표합니다.
6. 학사일정 승인과 ICS 받기, 세션 초기화 뒤 기본 사례 복구를 확인합니다.
