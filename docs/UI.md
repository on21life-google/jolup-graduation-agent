# 화면·에이전트·일정 연결

담당 계획상 우수진의 모듈은 `app.py`, `jolup/agent.py`, `jolup/calendar.py`, `jolup/mcp_client.py`, `jolup/mcp_server.py`입니다. 학점 계산과 수강 후보 선택은 윤석현의 모듈을 그대로 호출하고, 결과를 화면에 표시합니다. 2026-10-26 우수진의 디자인·월간 일정·관심 목록 시안을 실제 엔진에 연결했습니다. 제출 기여와 통합 재구현은 [팀원 통합 결과](팀원_통합결과.md)에 구분했습니다.

## 실행과 시연 순서

프로젝트 폴더에서 `.venv/bin/python -m streamlit run app.py`를 실행합니다. 브라우저에서 `http://localhost:8501`을 엽니다. Windows 실행 검증은 2026-10-23 사용자 결정으로 이번 범위에서 제외합니다.

1. 왼쪽에서 더미 사례를 선택하고 **사례 불러오기**를 누릅니다.
2. **진단·수강 계획**에서 현재 확정 이수와 목표까지의 계획을 구분해 확인합니다. 수강 중 학점은 별도 지표로 표시합니다.
3. **대화로 확인**에서 **나 졸업 괜찮아?**를 누릅니다. 목표까지의 준비 상태와 현재 졸업요건을 함께 말하며, 답변, reason, 근거자료, meta 네 부분을 확인할 수 있습니다. “지금 졸업요건 충족했어?”는 현재 판정을 먼저 보여 줍니다. 이어 “그럼 다 채울 수 있어?”라고 질문하면 같은 학생의 수강 계획을 확인합니다.
4. **계산 과정·출처**에서 각 과목의 취득 인정과 평점 반영을 구분하고 제외 사유를 읽습니다. 근거 카드에서는 표 머리글·예외를 포함한 페이지 문맥을 펼칩니다. 전망의 확인 필요 사유는 계획 전에 확인합니다. 이 내역은 계산 코드의 출력입니다.
5. **학사일정**에서 일정을 선택하고 날짜를 확인합니다. 승인 체크박스를 직접 선택한 뒤 ICS 파일을 받습니다. 외부 캘린더에 직접 등록하지 않습니다.

## LangGraph 실행 흐름

`START → route → 필요한 도메인 순차 실행 또는 이전 결과 재표시 → compose → explain → END`로 실행됩니다. 단일 질문의 기존 intent를 유지하면서 명시적으로 요청한 여러 영역을 `requested_intents`와 `sections`로 묶습니다. 규정·현재진단·일정을 함께 물으면 각각의 상태와 근거가 표시되고, 일부 영역의 실패가 다른 영역의 성공으로 가려지지 않습니다. 현재 진단과 계획이 겹치면 계산을 재사용합니다. 모델이 행동을 계속 재선택하는 자유 ReAct 루프는 구현하지 않았습니다.

로컬 모드에서 AI 연결을 켜면 공통 `classify_intent`를 통해 실제 모델이 질문 유형을 분류합니다. 입력은 원문 질문 대신 졸업·수강계획·일정 등 고정된 도메인 신호와 이전 의도 유형뿐입니다. API 실패나 불명확한 결과는 로컬 분류로 처리하고 화면에 표시합니다. 키 없는 실행은 로컬 분류임을 구별합니다. 성적 조작·비밀키 요청 등은 API 호출 전에 차단합니다.

`respond()`는 항상 `answer`, `status`, `rows`, `evidence`, `meta`, `intent`, `timings`와 허용된 요약으로 만든 `study_trace`를 반환합니다. 학생 진단·계획에 필요한 프로필이나 성적표가 없으면 확인 필요를 반환합니다. 공개 규정 질문에는 학생 기록을 요구하지 않습니다. 범위 밖 요청, 성적 조작, 포털 실행 요청은 수행하지 않습니다.

모델 호출은 공식 `langchain-openai`의 `ChatOpenAI`와 `langchain-anthropic`의 `ChatAnthropic`을 사용합니다. `jolup/llm.py`는 공급자 설정·입력 범위·오류 표시를 통일하는 앱의 경계입니다. 상위 `langchain` 패키지는 필요하지 않아 설치하지 않았으며, 이를 LangChain 미사용으로 해석하지 않습니다. 의도 분류는 `IntentDecision`, 앱의 설명 선택은 `ExplanationSelection` Pydantic 모델을 `with_structured_output(method="json_schema")`에 전달합니다. 일반 `generate()`의 기본 문장 스키마 `ExplanationOutput`과 실제 앱의 선택 스키마는 구분합니다. OpenAI에는 strict 스키마를 적용합니다. 형식 검증이 설명 내용의 사실 정확성을 보장하지는 않습니다. LangGraph가 없어도 같은 흐름을 일반 분기문으로 만들 수 있으나, 현재 구현에서는 각 단계와 상태 전이를 명시적으로 검토하기 위해 사용합니다.

## 공통 AI 연결

아래 AI 연결은 로컬 모드 기능입니다. `JOLUP_AGENT_API_URL`을 설정한 HTTP 모드에서는 FastAPI `/chat`으로 계산·검색하고 AI 설명 체크박스가 비활성화됩니다. UI 키는 서버로 전달하지 않습니다.

API 키 입력은 비밀번호 필드입니다. `서비스=자동 인식`과 기본 모델 설정에서는 식별 가능한 OpenAI·Claude 키를 교체해 같은 화면에서 서비스를 바꿀 수 있습니다. 인식할 수 없는 키는 서비스를 직접 선택합니다. **대화 답변에 AI 설명 추가**가 켜진 경우에만 API를 호출합니다.

AI 설명은 계산 결과 옆의 별도 설명입니다. `explanation_facts()`가 허용된 계산 필드로 문장을 만들고 모델은 `fact_ids`만 선택합니다. `explain_result()`는 허용 ID·중복을 검사한 뒤 로컬 문장을 표시합니다. 진단·계획에서 해당하는 현재 판정·위험 또는 조건·자료 누락·상담 범위 문장은 모델이 생략할 수 없습니다. 규정·일정 조회에는 학생 진단을 임의로 붙이지 않습니다. 모델이 새 학점·URL·판정 문장을 쓰거나 `answer`, `status`, `rows`를 덮어쓰지 않습니다. 이 제한은 설명의 임의 생성을 줄이며 학교 원문·계산 규칙 자체의 정확성은 별도로 검증합니다. 이름·학번·질문 원문·성적표 원문·대화 원문은 API로 전달하지 않습니다. API가 실패해도 로컬 계산표는 유지됩니다. 로컬 환경에 키가 있어도 화면에서 AI 연결을 켜기 전에는 호출하지 않습니다. 실제 키가 없는 테스트는 모의 HTTP 테스트와 구별해야 합니다.

## 실행 과정과 선택적 LangSmith 연결

새 질문의 마지막 답변 아래 **실행 과정 살펴보기**를 펼치면 실제 호출 단계·상위 단계·함수와 파일·소요 ms·상태가 나타납니다. **살펴볼 실행 단계**를 선택하면 허용된 계산 요약을 볼 수 있습니다. 관찰 기록은 AI의 내부 생각이 아니며, 모든 Python 함수나 최적화 내부 반복을 자동 추적한 것도 아닙니다. 로컬 관찰에는 API 키가 필요하지 않습니다.

사이드바 **LangSmith 학습 기록 · 선택**은 답변 생성과 별도 설정입니다. LangSmith API 키, 프로젝트(기본 `jolup-study`), US/EU 리전, 선택적 워크스페이스 ID를 받습니다. 입력만으로 전송하지 않습니다. **이 더미 실행을 LangSmith로 보내기**를 누른 완료 기록만 공식 REST API로 전송하고 새 LLM 호출을 만들지 않습니다. OpenAI·Claude 키를 LangSmith 키로 사용할 수 없습니다.

HTTP 모드의 서버 실행 단계는 화면에서 열람할 수 있지만 LangSmith 내보내기는 지원하지 않습니다. API 프로세스에서 서명한 기록을 Streamlit 프로세스의 내보내기 검증으로 승인하지 않습니다.

로컬 외부 전송은 내장 더미를 선택했고 프로필·과목이 해당 더미와 일치하는 경우만 허용합니다. CSV 업로드·수정한 학생 조건·내장 선택 출처 미확인은 로컬 관찰만 가능합니다. 기록에는 고정된 단계/함수, 시간, 허용된 상태와 숫자 집계를 남기며 질문·성적표·프로필 원문·AI 문장·예외 원문·API 키를 넣지 않습니다. 성공한 실행 ID는 세션에서 중복 전송을 막습니다.

**전송 요청 수락**은 REST 서버의 수락 결과이며 클라우드 내용을 다시 조회했다는 뜻은 아닙니다. 오류 시 일부 단계가 전송됐을 수 있고 자동 재시도하지 않습니다. 자세한 절차는 [LangSmith 안내](LANGSMITH.md), 그림·코드·실습의 연결은 [학습 가이드](학습_가이드.md)를 봅니다.

## 메모리와 초기화

업로드한 CSV, 학생 상태, 채팅 결과와 화면에 입력한 API 키는 기본적으로 Streamlit `session_state`에 저장합니다. 사용자가 **키 포함 .env 다운로드 준비 → .env 파일 다운로드**를 선택하면 입력한 생성 API 설정을 별도 다운로드할 수 있습니다. 이 명시적 내보내기는 자동 저장·로그 기록과 구분하며 LangSmith 키는 포함하지 않습니다. 성적표를 디스크·벡터 DB·로그에 기록하지 않습니다. **세션 초기화**는 이 상태와 로컬 학습 기록·LangSmith 키·일정 승인 상태를 제거하고 기본 더미 사례로 돌아갑니다. 이미 전송한 LangSmith 기록을 외부 서비스에서 삭제하는 동작은 아닙니다. 사례 교체나 성적표 교체 시 이전 대화 결과를 제거해 다른 학생의 상태와 섞이지 않게 합니다.

로컬은 session_state의 `ConversationMemory`, HTTP는 API의 세션별 메모리에 최근 4턴의 검증된 결과를 보관합니다. API에는 최대64세션을 두고 오래 사용하지 않은 세션부터 제거합니다. 입력·학교자료의 내용이 바뀌면 기억을 무효화하고, “아까 진단 다시 보여줘”처럼 명시적인 요청만 이전 결과를 재표시합니다. 새로운 조건이나 제약이 붙은 질문은 다시 계산합니다. 임의의 history/result를 HTTP 요청으로 받아 사실처럼 재사용하지 않습니다.

사례·프로필·CSV 교체 및 초기화 시 로컬 기억을 비우고 HTTP 세션 삭제를 요청합니다. 삭제 실패는 화면에 표시하지만 이전 세션 ID는 버립니다. 서버 재시작 시 서버 기억도 사라집니다. 그래프 실행은 `tracing_context(enabled=False)`로 감싸고 외부 콜백을 전달하지 않아, 셸에 LangSmith 환경 변수가 있어도 프로필·성적표·API 설정을 자동으로 외부 추적 서버에 보내지 않습니다. 선택적 더미 내보내기는 이 원본 그래프 상태와 분리한 허용 요약만 사용합니다. 자료 누락 사례의 빈 학기 수는 그대로 `None`으로 유지하며 0으로 바꾸지 않습니다.

일정 승인 키에는 선택한 일정 전체의 해시가 포함됩니다. 선택이나 날짜가 바뀌면 기존 승인으로 파일을 만들 수 없습니다. ICS의 종료일은 마지막 날짜의 다음 날이며, 일정 ID는 반복 다운로드해도 같습니다. 공식 자료에 없는 일정이나 미리보기의 날짜를 변조한 일정은 생성 함수에서도 거부합니다.

## MCP

기본 로컬 전송: `.venv/bin/python -m jolup.mcp_server`.

HTTP 전송: `.venv/bin/python -m jolup.mcp_server --transport streamable-http`. 기본 주소는 `127.0.0.1:8000/mcp`입니다. 서버 설정은 `MCP_HOST`, `MCP_PORT` 환경 변수로 조절합니다.

도구는 `parse_transcript`, `check_requirements`, `search_courses`, `search_scores`, `create_calendar_event`, `search_regulations`, `search_academic_events`, `plan_courses`, `answer_regulations`입니다. `search_academic_events`로 먼저 미리보기를 얻은 후 사용자가 승인한 경우에만 `approved=true`를 전달합니다. stdio의 stdout은 프로토콜 전용이며 학생 자료를 출력하지 않습니다.

`MCP_URL`이 없으면 같은 Python 함수를 직접 호출합니다. Compose 앱에 `MCP_URL=http://mcp:8000/mcp`를 지정하면 CSV 검증·진단·계획·규정 답변·일정 조회·ICS 생성이 실제 MCP HTTP 도구를 통해 실행됩니다. MCP 서버에는 이 변수를 지정하지 않습니다. Compose 기본 채팅은 app→api→mcp→chroma의 4서비스를 연결합니다. 서버는 `MCP_HOST=0.0.0.0`, `MCP_PORT=8000`으로 내부 통신하며 UI와 Swagger용 API만 127.0.0.1에 공개합니다. 원격 공개 MCP 서버로 학생 자료를 보내지 않도록 로컬 주소와 Compose의 `mcp` 주소만 허용합니다. 서버 오류를 로컬 성공으로 숨기지 않습니다.

## 검증

`python -m pytest tests/test_agent.py tests/test_calendar.py tests/test_app.py`로 검증합니다. AppTest는 11개 더미 사례, CSV 업로드와 식별정보 제거, 키 교체, 승인 전 다운로드 불가, 일정 변경 시 승인 초기화, 세션 초기화를 화면 위젯에서 시험합니다. 일정 테스트는 한국어 제목, 마지막 날 포함, 연도 경계, 안정적인 ID, 승인·변조 방지를 확인합니다. MCP 테스트는 실제 stdio와 HTTP subprocess를 띄우고, 도구 호출 및 HTTP를 경유하는 실제 Streamlit AppTest까지 수행합니다. 키 교체 테스트의 API 응답은 모의 응답이며 실제 외부 API 호출 검증과는 별개입니다.

관찰 기능은 `tests/test_observability.py`와 `tests/test_app.py`의 학습 기록 관련 시험을 함께 봅니다. 허용된 필드만 남기는지, 입력 변경·업로드·기록 변조를 차단하는지, 키 입력만으로 전송하지 않는지, 성공 후 중복 전송을 막는지 확인합니다. 실제 LangSmith 계정 전송·클라우드 화면 확인 여부는 [검증결과](검증결과.md)에 별도로 기록합니다.


혼합 질문·4턴 기억은 `tests/test_agent_conversation.py`, HTTP 채팅·세션·오류는 `tests/test_chat_api.py`와 `tests/test_chat_client.py`, UI 모드·초기화는 `tests/test_app_conversation.py`를 읽습니다.
