# 교수 실습 코드와 졸업로드맵 구현 비교

2026-10-26 수령 자료 기준이다. 실습 ZIP9개의 압축 내부 경로를 목록화하고, Python·노트북 소스 셀·설명·의존성을 읽어 비교했다. 중복본은 SHA로 식별했다. **교수 코드를 실행하거나, 노트북에 저장된 출력·API 키를 검증 근거로 사용하지 않았다.** 제품에서 수행한 테스트와 교수 예제의 읽기 검토를 구분한다.

이 보고서의 목적은 같은 기술을 더 많이 넣는 것이 아니라 요구·예시·프로젝트 선택을 구분하고, 누락을 고쳤는지 코드에서 확인하는 것이다. 보안·성능의 새 목표, Windows 시험, 시연 영상은 이번 범위 밖이다. 팀원의 담당 계획은 실제 작성 기여와 구분한다. 10/26 수령본의 실제 반영과 누락된 rag 구현의 한계는 [팀원 통합 결과](팀원_통합결과.md)를 따른다.

## Day4·Add-on: 혼합 질문과 기억

이 비교 전 제품은 일정 단어가 있으면 졸업 진단을 놓칠 수 있었고 이전 규정 재요청도 다시 검색했다. 이를 실패 기대값으로 남기고 [agent.py](../jolup/agent.py)·[conversation.py](../jolup/conversation.py)를 보완했다.

수업의 직원ID·휴가 도구를 그대로 복사하지 않고 가상 학생·과목·학사 일정 계약으로 바꿨다. 수업에서 서버 LLM이 실행된다는 사실을 HTTP AI off인 현재 제품에도 동일하게 적용됐다고 설명하지 않는다.

## 시험과 학습 순서

이번 혼합·기억·HTTP 보완은 새 실패 기대값을 만든 뒤 구현했다. core 관련68개 시험과 agent/conversation 문장·분기100%는 도메인 스텁을 포함한 해당 모듈의 검증이다. 일반 규정의 빈 프로필과 혼합 질문에서 학번을 행사 연도로 오인하는 경우도 실패 시험 뒤 수정했다. 기존 앱 전체가 처음부터 TDD로 개발됐다는 주장은 하지 않는다. 최종 전체 테스트·커버리지·Sonar·Docker 상태는 [검증 기록](검증결과.md)을 따른다. 과거722개100% 수치를 수정된 코드에 그대로 붙이지 않는다.

- 10/26 최종 동결본 Sonar에서 S3776 경고0건·coverage100%·중복0%를 확인했다. **Gate는 ERROR**이며 새 지적12건(리터럴7·응답 명세5), 열린 전체39건이 남는다. 응답 명세 경고는 현재 생성된 OpenAPI에 해당 상태코드가 있음을 별도로 확인했다. 복잡도 해소와 전체 Gate를 섞지 않는다. [규칙별 판단과 근거](SONARQUBE.md)
- API/client/명세/Postman 계약64개와 소유3모듈336문장·40분기100%는 해당 부분 시험이다. 전체 프로젝트 커버리지와 구분한다.
- 최신 실제 Postman은 **21요청·60assertion 통과**, 로컬8003·lexical 검색·AI off·일정승인false 조건이다. 이전17단계 벡터/승인true 기록과 다른 실행이며 서로 섞지 않는다. Postman 클라우드 업로드·Desktop Import·직접 MCP 요청은 검증한 것으로 확대하지 않는다.
- Swagger의 명세 예제를 시험으로 실행해 공개 규정 질문의 빈 프로필 처리 문제도 고쳤다. 브라우저가 열린 것과 모든 예제가 맞는 것은 다른 검증이다.
- 수업 예제는 원문 읽기 검토이고, 프로젝트 테스트가 교수 예제를 실제 계정으로 실행했다는 증거는 아니다. API 호출 비용이나 별도 외부 등록 없이 가능한 검증만 수행했다.

1. [test_agent_conversation.py](../tests/test_agent_conversation.py)의 혼합 질문·이전 결과·변경 무효화 기대값을 읽고 `agent.py`·`conversation.py`를 따라간다.
2. [test_chat_api.py](../tests/test_chat_api.py)에서 세션·삭제·LRU·오류 코드를 읽고 `study_api.py`의 요청→결과 계약을 확인한다.
3. [test_chat_client.py](../tests/test_chat_client.py)에서 local/HTTP 선택·통신실패를 읽고 화면의 대화 경로와 연결한다.
4. [청크 품질점검](청크_품질점검.md)에서 무잘림·검색 hit·최종 답변 인용을 분리해서 읽는다. 벡터DB 이름보다 실제 입력·출처·정답이 비교 기준이다.
5. [프로젝트 구조도](프로젝트_구조도.md)와 [아키텍처 의사결정](아키텍처_의사결정.md)에서 파일·경계·선택 이유를 찾고 [API 실습](API_EXPLORER.md)의 동일 요청을 실행한다.

현재 판단은 **혼합 요청·명시적 결과 재사용·HTTP 경계를 추적하고 시험하기 쉬워졌다**는 범위다. 수업 코드보다 모든 측면에서 우수함, 모든 모범사례 충족, 모든 질문의 정답을 보장한다는 뜻은 아니다. 남은 실제 Docker 실행과 팀 파일 통합도 완료로 바꾸지 않는다.
